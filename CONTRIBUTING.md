# Contributing to Video Trimmer

Thanks for considering a contribution. Video Trimmer is a small, free, open-source tool; issues and PRs of any size are welcome.

## Dev setup

Requires Python 3.11 on Windows.

```bash
git clone https://github.com/awesomo913/video-trimmer.git
cd video-trimmer
uv venv --python 3.11 .venv
uv pip install --python .venv -r requirements-dev.txt
.venv/Scripts/python main.py
```

No ffmpeg install is needed: the `imageio-ffmpeg` package ships one and `services/ffmpeg_locator.py` finds it.

## Tests, lint, build

```bash
.venv/Scripts/python -m ruff check .
.venv/Scripts/python -m pytest -q
.venv/Scripts/python build.py        # dist/VideoTrimmer.exe
```

Tests never open a window. Anything that needs real media uses a 2-second clip generated by the bundled ffmpeg (tests marked `ffmpeg`), so they run the same on CI.

## Architecture

```
main.py              entry point: sets up the log file, starts the window
app.py               main window: layout, key bindings, drag-and-drop, wiring
config.py            colours, fonts, formats, quality presets, constants
services/
  ffmpeg_locator.py  finds ffmpeg (bundled first, then PATH) and optional ffplay
  ffmpeg_service.py  metadata (parsed from `ffmpeg -i`), trim command, progress, cancel
  video_service.py   OpenCV preview: frame reads, thumbnails, threaded playback engine
  batch_split_service.py  scan a folder, work out segments, run trims one at a time
  edit_transforms.py crop / rotate / flip for the preview and the ffmpeg filter
  ui_bridge.py       hands results from worker threads to the Tk thread
  applog.py          log file under %LOCALAPPDATA%\VideoTrimmer\logs
  fsutil.py          same-file check, non-clobbering file names
widgets/             CustomTkinter widgets (toolbar, timeline, trim controls, export dialog, batch panel...)
tests/               pytest suite
```

**Data flow.** Open a file: OpenCV opens a capture for preview and ffmpeg reports the details. Frames travel from a playback thread to the window through `queue.Queue(maxsize=3)`; the window polls it. The timeline is a `tk.Canvas` (the only widget that can draw thumbnails, two draggable handles and a playhead). Export runs `ffmpeg` in a worker thread and parses `time=` from stderr for progress.

### Things worth knowing before you change them

- **Services never import tkinter.** Widgets call services; services call back from worker threads, and `ui_bridge.MainThreadDispatcher` moves those callbacks onto the Tk thread. Do not call widget methods (or `after`) from a worker thread.
- **One ffmpeg, no ffprobe.** `get_metadata()` parses the banner of `ffmpeg -i file`. If you change the parser, add a sample banner to `tests/test_ffmpeg_parse.py`.
- **Stream copy cuts at keyframes.** With "Copy" quality the cut snaps to the keyframe at or before the start time. Frame-accurate cuts need a quality preset (re-encode). This is a property of video, not a bug.
- **Seek before the input** (`-ss` then `-i`) is fast; `-t` gives the length. The trim range is validated in `validate_trim()` before ffmpeg is started.
- **The source file is never overwritten**: `run_trim` refuses a destination that is the same file as the source, and batch outputs get ` (2)` suffixes rather than replacing earlier results.
- **Playback is wall-clock paced.** The playhead follows real time (the same clock `ffplay` audio uses) and drops frames when decoding falls behind, instead of slowing down. `VideoCapture` is not thread-safe: only the playback thread reads while playing; `PlaybackEngine.stop()` joins the thread before the capture is released.
- **Preview audio** is an `ffplay` child process (optional). It is restarted on seek and killed on pause.
- **Packaging:** `build.py` collects `customtkinter`, `tkinterdnd2` (native drag-and-drop library) and `imageio_ffmpeg` (the ffmpeg binary) as data. Forgetting one of these makes the frozen exe fail in ways that the source run does not show.
- Windows only: the app uses `CREATE_NO_WINDOW` and Windows DPI calls (guarded, so imports still work elsewhere).

## Code style

- Small functions, early returns, type hints.
- No bare `except:` and no swallowed exceptions: catch specific errors, log them, tell the user. A windowed exe has no console, so the log file is the only trace.
- Use `logging` (`log = logging.getLogger(__name__)`), not `print()`.
- Keep UI colours and fonts in `config.py`.

## Good first issues

- Cut out a middle section (keep the beginning and end).
- Waveform on the timeline.
- Audio-only export (extract the sound).
- A progress estimate (time remaining) in the export dialog.

## Pull request checklist

- [ ] `ruff check .` passes
- [ ] `pytest -q` passes
- [ ] No new silent exception handling
- [ ] No widget calls from worker threads
- [ ] `CHANGELOG.md` updated under a new heading if the change is user-facing
- [ ] Description explains why, not just what
